# Harbor — Phase 6: Retrieval-Augmented Generation with Groq

## Objective

Phase 6 converts Harbor's semantic retrieval pipeline into a grounded
support question-answering system.

## Architecture

User Question
→ Query Embedding
→ Supabase pgvector
→ Relevant Chunks
→ Context Builder
→ Groq LLM
→ Grounded Answer
→ Citations

## Embeddings

Harbor uses:

sentence-transformers/all-MiniLM-L6-v2

Embedding dimension:

384

Embeddings run locally.

## LLM Provider

Harbor uses Groq for language-model generation.

The selected model is configured using:

GROQ_MODEL

and the secret key using:

GROQ_API_KEY

## Grounding

Groq is instructed to answer only from retrieved Harbor knowledge.

Unsupported facts must not be invented.

## No-Answer Behavior

If retrieval finds no qualifying knowledge, Harbor skips the Groq
request and returns:

"I don't have enough information in the Harbor knowledge base to
answer that question."

## Citations

Citations are generated by Harbor from retrieval metadata rather than
being invented by the LLM.

Current citation data contains:

- source
- chunk index
- similarity
- metadata

## Prompt-Injection Protection

Retrieved knowledge is treated as untrusted reference material.

Instructions contained inside retrieved documents must not override
Harbor's system instructions.

## Evaluation

Phase 6 evaluates:

- retrieval hit rate
- groundedness
- citation correctness
- no-answer accuracy

## Authentication

The RAG API remains protected by the JWT authentication system created
during Phase 3.

## Current Limitation

Precise page-level PDF citations are not yet guaranteed because page
metadata still needs to be propagated from the loader to individual
chunks.
